## What the app is today

Every row in [REQUIREMENTS.md](REQUIREMENTS.md) is `Done` except two explicit `Deferred` rows. The
application includes:

- ordinary UTF-8 Markdown documents through `NSDocument` — New, Open, Save, Save As, autosave,
  Versions, tabs, Recents, undo/redo, spelling, Find, and printing;
- formal GFM 0.29 parsing through pinned direct cmark-gfm, with a live-styled literal Source mode
  and a delimiter-free editable WYSIWYG mode over the same source;
- semantic formatting commands on one window-scoped command model with menu, toolbar, and
  shortcut parity; task, link, table-cell, and image interactions;
- exact-copy PNG/JPEG/GIF/HEIC/HEIF placement into a shared sibling `assets/` directory as one
  contained, non-destructive transaction;
- Swift 6 complete concurrency, privacy-safe local-only instrumentation, and per-run JSON Lines
  diagnostics whose payloads cannot represent document content;
- process-level smoke verification, a passive window-only screenshot verifier, and a committed
  screenshot gallery (`docs/screenshots/`, regenerated by `Scripts/screenshots.sh`).

Two verification programmes closed before this queue opened: the **editor foundation rewrite**
(COR-18 – COR-31, typography, TextKit application, scheduling, native command surface) and the
**conformance and liveness programme** (COR-26 – COR-30, then COR-68 – COR-85, which audited every
requirement family against observed production evidence and closed the last two `Correction` rows).

Ordered by VISION's objective priority, not by discovery order: external file truth (objective 1)
precedes command responsiveness (objective 7). COR-86 leads only because it is small and
everything after it wants the measurement. COR-89 was re-planned twice. Stage 0 falsified its original premise — the rebuild it proposed to
bound is only 25–28 % of a command — and phase 1's instrumentation then found the real cause: the
same pure work ran repeatedly. The authoritative rebuild ran **three times** per command (twice as
validation) and the candidate text was parsed **twice**. Memoising both, deleting no validation and
computing nothing new, cut Release worst case by 3–8×.

REQ-143 is `Done`: the 16 ms budget binds on every corpus shape not declared a stress shape, and
`heavyLists` and `tableDense` carry recorded bounds instead. See `DECISIONS.md` for the criteria,
the rejected alternatives, and the respect in which the chosen one is worse.

## Next

**TOUR-01 — the whole app, used as a person uses it** (✅ Done, 2026-11-27). A long scenario,
`Scripts/agent-drive/tour.txt`, drives every feature on a Mac runner from a plain launch to a
relaunch (`.github/workflows/agent-drive.yml`), and each defect it finds is fixed with a test that
fails for it where one can. It found: no window at a plain launch, a stamp-sized window, no
keyboard focus in a new window, Block Quote's shortcut locking the screen, a second parse at every open, and in
WYSIWYG no spaces at a line's end, no Return and no Backspace (REQ-152, REQ-153). Then:

- typing discarded by another app's write, since an open typing group read as clean;
- a hang when closing a window after typing;
- Add Image refused after the caret moved;
- no Find menu, and no ⌘W;
- the caret lost on returning from Source mode;
- quote text and code backgrounds left in Light colours after a switch to Dark;
- the keyboard nowhere after closing the find bar;
- an alert waiting for the person recorded as a main-actor stall;
- an image overlapping the text after it;
- no File › Open Recent, since SwiftUI dropped the item AppKit added;
- no Duplicate, Rename or Move To, though the document autosaves in place, and a duplicate
  showing its original's images as missing, as the Versions browser showed a past version's;
- every autosave holding the main thread for its whole write, 133–413 ms on a runner, while the
  person typed;
- the Versions browser's animation and a duplicate's close dialog recorded as main-actor stalls;
- no Print or Page Setup in the File menu, so ⌘P never printed, a gap every earlier tour missed
  because its print step looked only for faults;
- saving a moment after typing hung the app, as did any save after Print was cancelled.

It ran through on 7ab3517 twice, every step and expectation holding: 340 steps, 77 checks, and no
fault or error in the app's log but the one section Q expects (runs 46001113929, 46001121084).
It runs on every pull request that changes the driver or the tour, and on demand.

**Packaging and distribution** (🔵 Active, 2026-11-26). Cloud-first development is in place:

- CI on GitHub's `xcode-27` runner;
- a Sparkle updater (REQ-033, REQ-034);
- a release workflow that publishes a signed disk image and the update feed for every `main`
  commit that changes the app (`DECISIONS.md`, 2026-11-26; `DEVELOPMENT.md`).

An installed copy updates itself: the owner reported it on 2026-11-27, after v1.0.3–v1.0.6, which
closes REQ-033. v1.0.0 could not start, because an ad hoc build cannot load its own
`Sparkle.framework` under the hardened runtime (`DECISIONS.md`, 2026-11-26). Since then every release
launches its exact bundle twice before publishing, and its feed, archive signature (with a
tampered-copy control), update key and entitlements are checked from the public download URLs.

Still open:

- The five-minute budget. The first green run (CI 45855830007, 628 tests) took 5m12s from push to
  `CI gate`. Once the screenshot step stopped rebuilding the app, CI 45858255326 took about 4m50s,
  3m33s of it in `check.sh`, with an empty compilation cache. Measure again after the first merge
  saves that cache.
- The first window's cost. On a runner booted minutes earlier, the first launch's
  `makeWindowControllers` took 2.9 s on the main thread (repeat-smoke 45924758118), mostly
  paging AppKit from a cold disk. A release allows that stall on its first launch only
  (`DECISIONS.md`, 2026-11-27). On warm launches the same call is 240–280 ms on a runner. Of
  that, our two editors are about 50 ms, much of it AppKit's one-time text-input set-up, which
  either editor would pay first. A second full layout was another 80 ms, and it is gone: the
  window is created at its final size (`theDocumentWindowIsCreatedAtItsFinalSize`). Building the
  Source editor lazily would save roughly another 10–20 ms, and REQ-052's persistent editors make
  it a larger change than that is worth. A warm profile of three ⌘N opens (probe 46014139254)
  found no hotspot left in the first layout, and removed the tab merge that was over half of
  showing the window (`DECISIONS.md`, "New documents tab as the person's Prefer tabs setting
  says"). Nothing measures this on a real Mac yet.
- Mac runners that never come. Twice on 2026-11-26 a `main` job waited 15 minutes for an
  `xcode-27` runner and was dropped (CI 45860219913, Release 45866221874 attempt 1), while
  pull-request jobs started within a minute. Both ended after exactly 15 minutes with no runner and
  no steps: GitHub never assigned one. That is outside this repository's code, so
  `retry-unstarted.yml` now asks again, once or twice, instead of leaving `main` red until a
  person notices. A dropped job still costs its 15 minutes against the five-minute budget.
